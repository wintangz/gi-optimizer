# Architecture & Shared Contracts

Binding for every feature (`good-import`, `single-character-optimizer`, `akasha-presets`,
`official-presets`, `custom-teams-and-presets`, `performance`, `visual-identifiers`). Features are referred to by slug only.
The constitution is in `.specify/memory/constitution.md`.

## Layout

```text
apps/web/                 Next.js (App Router) static export — UI only, no server code
packages/good/            GOOD schema, parser, plain-language error reporting   (good-import)
packages/engine/          GO adapter: GOOD -> GO ArtCharDatabase, preset -> GO team,
                          rotation evaluation, optimization via GO's GOSolver  (single-character-optimizer)
packages/presets/         Preset schema (src/schema.ts, CONTRACT), validation, account
                          matching, bundled akasha/official preset JSON        (akasha-presets, official-presets)
tooling/go-paths.mjs      Resolves @genshin-optimizer/* to vendor/genshin-optimizer (shared by Vitest + Next)
vendor/genshin-optimizer  git submodule, GO source pinned at aa908fd (MIT). NEVER edit.
specs/<slug>/             Spec Kit artifacts per feature (spec, plan, tasks, ...)
```

Later (do NOT create): `apps/server` (accounts / preset storage only), `team-total-optimizer`,
community preset library, quick-register accounts.

## Damage engine = GO itself

Proven by `packages/engine/test/spike.test.ts`: GO's own code path computes damage headlessly.

```text
GOOD JSON ──► new ArtCharDatabase(1, new SandboxStorage()).importGOOD(good,false,false,false)
preset    ──► db.teamChars.new(key, {conditional, customMultiTargets:[rotation], hitMode, ...})
              db.buildTcs.new(...) for 'tc' teammates; db.teams.new({loadoutData, conditional, enemyOverride})
          ──► getTeamData(db, teamId, targetTeamCharId, 0, overrideArt?, overrideWeapon?)   [GO libs/gi/ui/src/hooks/useTeamData.ts]
          ──► uiDataForTeam(teamData, gender, activeCharKey)[target].target                [GO uidata]
          ──► display path ['custom', '0'] = rotation total (GO custom multi-target sum)
Optimizer ──► exactly GO TabOptimize.generateBuilds: workerData + dynamicData, optimize(nodes),
              new GOSolver(problem, status, maxWorkers).solve()  — GOSolver runs Web Workers.
```

Rules:
- Never re-implement a formula. If something can't be expressed through GO's sheets /
  conditionals / custom multi-targets / bonusStats, it is out of scope — log it.
- Rotation total = GO custom multi-target value × `rotation.repeat`. Per-instance breakdown
  = each CustomTarget's node value × weight.
- **ER**: never weighted in the objective. ER floor is an optional user constraint
  (GO statFilter on `enerRech_`). ER-scaling buffs that are part of GO formulas (e.g. Emblem of
  Severed Fate, Raiden burst) stay as GO computes them (GO fidelity wins; logged assumption A1).
- Golden fixtures: `packages/engine/test/golden/*.json`, generated by
  `packages/engine/scripts/capture-golden.ts` that drives GO's **unmodified** `getTeamDataCalc`
  with GO-native team objects; our preset→GO adapter must reproduce each value within
  relative error ≤ 1e-3 per instance. Additionally the app can export a GO database JSON
  ("Verify in GO") that the user imports into the live GO site to cross-check by eye.

## Engine API (packages/engine/src/index.ts) — CONTRACT

```ts
export type ArtifactSlot = 'flower'|'plume'|'sands'|'goblet'|'circlet'
export interface BuildSelection { weaponId?: string; artifactIds: Partial<Record<ArtifactSlot, string>> }
export interface InstanceResult { label: string; path: string[]; count: number; perHit: number; subtotal: number }
export interface RotationResult { total: number; instances: InstanceResult[]; stats: Record<string, number> /* final atk,hp,def,eleMas,critRate_,critDMG_,enerRech_, ... */ }
export interface OptimizerSettings {
  erFloor?: number                         // e.g. 1.6 = 160%; undefined = no floor
  includeEquippedOnOthers: boolean         // GO "use equipped artifacts" (excludedLocations)
  excludedCharacters: string[]             // artifacts on these chars are never used
  lockedOnly?: boolean
  mainStatAssumptionLevel: 0|4|8|12|16|20  // GO "Assume main stat level"
  levelLow: number; levelHigh: number      // artifact level filter
  setExclusion?: Record<string, (2|4)[]>   // GO artSetExclusion
  topN: number                             // builds to keep (default 5)
}
export interface OptimizeResult { builds: Array<BuildSelection & { total: number }>; tested: number; skipped: number; durationMs: number }

export function createSession(good: unknown): EngineSession     // hydrates GO db once per session (throws on non-GOOD)
export interface EngineSession {
  evaluate(preset: Preset, selection?: BuildSelection): RotationResult
  currentBuild(preset: Preset): BuildSelection                    // target's equipped weapon + artifacts
  optimize(preset: Preset, settings: OptimizerSettings, opts?: { weaponId?: string; onProgress?(p:{tested:number;skipped:number;total:number}):void; signal?: AbortSignal; maxWorkers?: number }): Promise<OptimizeResult>
  listTargets(characterKey: string): Array<{ path: string[]; name: string; section: string }>  // display paths for rotation builders
  listConditionals(characterKey: string): ConditionalDescriptor[] // for custom team builder
  exportGODatabase(preset: Preset, selection?: BuildSelection): object // "Verify in GO"
}
```

## Presets — CONTRACT

Schema: `packages/presets/src/schema.ts` (`presetSchema`, id `gi-optimizer/preset@1`).
- `source`: `akasha` | `official` | `user`. Same schema; only authorship/badge/leaderboard differ.
- Bundled JSON: `packages/presets/data/akasha/*.json`, `packages/presets/data/official/*.json`.
- User presets: IndexedDB store `presets`.
- Matching (`packages/presets/src/match.ts`): `matchAccount(preset, account): MatchReport`
  with one entry per requirement part (character owned, constellation, weapon key,
  refinement, level, talents) → `{ part, expected, actual, ok, message }` in plain English.
  Akasha presets with any failing part cannot run; nothing is substituted. Teammates with
  `build.type: 'tc'` need no ownership (Akasha assumes fixed teammate builds).
- Badges: akasha → "Akasha · <label>" + verified only if golden fixture exists;
  official → "Official"; user → "Custom — use at your own risk", no verification badge.

## Web app (apps/web) — CONTRACT

Routes (static): `/` home, `/import` (good-import), `/optimize` (single-character-optimizer),
`/presets` (browse akasha + official + user), `/teams` (custom-teams-and-presets builder).
Shell/nav: `src/app/layout.tsx` + `src/components/Nav.tsx` (owned by bootstrap; add links only).
Shared visual identifiers: `packages/presets/src/metadata.ts` + `src/components/Identifier.tsx` (`CharacterBadge`, `WeaponBadge`, `ArtifactBadge`, `ItemIdentifier`) used across all routes so no character, weapon, or artifact is shown as text alone and simulated (`tc`) teammates receive a distinct `SIM` + dashed ring treatment.

IndexedDB (`idb` library), database `gi-optimizer`, owned by good-import, module
`src/lib/storage/db.ts`:
- store `good` — key `current` → `{ good: IGOOD, importedAt: string, fileName?: string, summary }`
- store `presets` — key preset.id → Preset (custom-teams-and-presets)
- store `settings` — key `optimizer` → OptimizerSettings (single-character-optimizer)
Exports: `loadGood()`, `saveGood()`, `clearGood()`, `listUserPresets()`, `saveUserPreset()`,
`deleteUserPreset()`, `loadSettings()`, `saveSettings()`; React hook `useGood()`.

GO code is heavy (sheets + MUI). Load the engine only on `/optimize` and `/teams` lazily,
client-side only (no top-level runtime imports of `@gi/engine` in route modules; route all evaluations, catalog queries, and optimizations through `src/lib/engine/workerClient.ts` backed by `src/workers/optimizer.worker.ts` holding a single hydrated `EngineSession`).

## Assumption log

Global assumptions live here; feature-specific ones in each `specs/<slug>/spec.md`.

- **A1 (ER)**: "ER does not enter the calculation" = ER is never part of the objective and no ER
  requirement is baked into presets. GO formula terms that convert ER into damage (Emblem,
  Raiden, Skyward Pride-type passives) remain because GO fidelity is non-negotiable.
- **A2 (Engine)**: GO's WR engine (live site path) is used, not GO's in-progress Pando engine.
- **A3 (Verification)**: "Verify against GO itself" is done by golden fixtures computed by GO's
  unmodified team-calc function plus a "Verify in GO" export for manual cross-check on the site.
- **A4 (Teammates)**: Akasha presets use fixed teammate builds (GO theorycraft builds); the user
  need not own teammates. Only the target character's ownership/cons/weapon/refinement is matched.
- **A5 (Weapon)**: for an `owned` target the user may pick any weapon instance from their own
  inventory (default: equipped). It must still meet the preset's weapon requirement.
- **A6 (Gender)**: Traveler gender defaults to 'F' unless the GOOD/settings say otherwise.
